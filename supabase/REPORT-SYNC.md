# Shiprocket scheduled report import

Verified delivery contract: application/json with `report_file`, an HTTPS CSV URL on `report-sr-mum.shiprocket.in`. The receiver only downloads from this exact host; redirects, other hosts, credentials and nonstandard ports are rejected.

## Install on the existing project

1. Run `migrations/20261026_report_v2.sql` if not already installed (safe to rerun), then `migrations/20261027_report_inbox.sql` in Supabase SQL Editor. These retain existing records.
2. Replace the existing **report-inbox** Edge Function code with **bundles/report-inbox.ts**, generated by `node scripts/bundle-report.mjs`. Deploy it. Keep Verify JWT OFF and the existing REPORT_WEBHOOK_TOKEN secret unchanged.
3. Keep Shiprocket's existing webhook URL/token and daily Last 30 Days schedule unchanged.
4. To process the already captured report: in the function's Test panel choose POST, add header `x-api-key` with the existing webhook token, and body `{"action":"process_pending"}`. Send the request. Success includes `"imported":true`, shipment/source-row counts and an import ID. Do not send the token in screenshots. Each invocation processes one oldest pending or failed delivery; repeat if needed.
5. Run the verification query below, then refresh the signed-in dashboard. Successful HTTP 200 capture from the old receiver alone does not demonstrate an import.

```sql
select received_at, state, import_id, last_error
from private.report_deliveries
order by received_at desc limit 5;

select filename, status, source_rows, expected_shipments, completed_at
from public.next_imports
where report->>'origin' = 'shiprocket-report'
order by created_at desc limit 5;
```

## Behaviour and limits

- Every new scheduled delivery now downloads, archives and imports synchronously. Matching shipments update; omitted orders are retained. Existing terminal-state and newer-status protection is reused. Refresh the dashboard to load new data.
- Exact source bytes are retained as a private gzip archive. Source item rows and unknown columns survive through the shared manual-upload mapping. SHA256 duplicate detection is transactional and serializes with existing import/event operations.
- Only service_role can call the new processing RPCs. The function delegates finalization to the configured first available primary uploader and restores the request identity afterwards. Browser upload privileges are unchanged.
- CSV must be UTF-8, up to 10 MiB and 20,000 lines. Downloads time out after 30 seconds. A malformed or unmappable report fails rather than importing a partial set. Larger reports need a background worker implementation.
- Failed work is retained and returns HTTP 500 with the failing step. Provider retry behaviour is not assumed. Use the authenticated-by-token `process_pending` action to retry; no additional timed retry job is installed. A timed-out process may remain awaiting_mapping; the same action retries it safely. An expired report URL needs a fresh report from Shiprocket.
- The Last 30 Days scheduler selects by AWB generation date, so older open shipments and orders without an AWB may be absent. Their existing records remain, but this report alone cannot keep omitted records current.
- An existing unfinished manual import of the identical file must be completed first. A previously completed identical file is reused, not duplicated.
